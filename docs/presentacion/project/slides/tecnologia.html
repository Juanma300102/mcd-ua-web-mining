CÓMO SE HIZO · TECNOLOGÍAS

Qué hace cada tecnología en cada paso

1 · Encontrar

requests · lxml

Lee los sitemaps diarios y la API de WordPress y saca la dirección y la fecha de cada nota.

2 · Descargar

requests · robots.txt · Dagster

Un pedido cada 2 s, reintentos a los 2, 8 y 32 s, y 34 particiones mensuales por medio.

3 · Limpiar y unir

BeautifulSoup · pandas · Parquet

Lee el JSON de Arc XP, quita el HTML, une los tres medios y elimina repetidas.

4 · Puntuar

PyTorch · Transformers · Ollama

Tres modelos leen título y bajada y dan la probabilidad de positivo, neutro y negativo.

5 · Resumir

pandas · SciPy

Promedios por semana y por mes, márgenes de error y el antes y después de cada hito.

6 · Contar

Python · HTML + SVG

Un script recalcula cada cifra del informe; la página dibuja los gráficos al abrirse.

En todo el recorrido:

Python 3.12 + uv

Docker + Postgres

pytest

Git + OpenSpec

Sin navegador automatizado: solo rutas que el robots.txt de cada sitio permite

Ahora, cómo se hizo. Todo es código abierto y corre en una computadora común. En cada paso actúa una herramienta distinta. Para encontrar las notas, requests pide los sitemaps, que son los índices que los diarios publican para los buscadores, y lxml los lee; para MisionesOnline usamos su API pública de WordPress. Para descargar, un cliente propio espera dos segundos entre pedidos, reintenta con esperas crecientes y respeta el robots.txt; Dagster reparte el trabajo en 34 meses por medio. Después BeautifulSoup y pandas limpian y unen, y todo queda en Parquet. Para puntuar usamos PyTorch y Transformers, y Ollama para el modelo grande. pandas y SciPy hacen los promedios y los márgenes de error. Y un script arma el informe. Por debajo, uv fija las versiones, Postgres en Docker guarda el historial de Dagster y pytest prueba todo sin salir a internet.
