Del sitio web a la tabla: qué hace cada herramienta

Los tres primeros pasos convierten miles de páginas web en un dataset. Solo usamos rutas públicas y permitidas por cada sitio, sin navegador automatizado.

1 · Encontrar las notas

requests pide los sitemaps diarios de Infobae y La Nación y la API de WordPress de MisionesOnline.

lxml lee cada sitemap (XML) y saca la URL y la fecha; quedan solo las de /politica/.

Dagster corre los dos catálogos una sola vez y guarda la lista.

2 · Descargarlas

Cliente propio sobre requests: 1 pedido cada 2 s por sitio, reintentos a los 2, 8 y 32 s.

robots.txt se consulta antes de cada pedido; por eso no usamos la API interna de La Nación.

Dagster parte cada medio en 34 meses: si uno falla, se repite solo ese.

3 · Limpiar y unir

JSON de Arc XP: cada página de Infobae y La Nación trae una ficha con título, bajada y cuerpo.

BeautifulSoup quita el HTML y deja solo el texto.

pandas + Parquet unen los tres medios, eliminan repetidas y guardan la tabla.

Si un sitio responde con un desafío anti-bot, el cliente se detiene: le pasó a MisionesOnline unas horas el 27/10

Ahora cómo se hizo, empezando por el scraping. Son tres pasos. Para encontrar las notas, requests pide los sitemaps, los índices diarios que los diarios publican para los buscadores, y lxml los lee y se queda con las direcciones de la sección Política; en MisionesOnline usamos la API pública de WordPress, que ya filtra por fecha. Para descargarlas armamos un cliente propio, cortés: un pedido cada dos segundos por sitio, reintentos con esperas crecientes, y antes de cada pedido consulta el robots.txt; por eso no usamos la API interna de La Nación, que lo prohíbe. Dagster reparte el trabajo en 34 meses por medio. Y para limpiar: Infobae y La Nación esconden en cada página una ficha JSON con título, bajada y cuerpo; BeautifulSoup saca el HTML, y pandas une todo en una tabla Parquet.
